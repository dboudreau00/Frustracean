# Example artefacts

Two files that let you exercise `frustracean replay` without running anything,
and that double as the specification the payload has to satisfy.

| File | What it is |
|------|------------|
| `testbed-plan.json` | A real hijack plan, generated by `frustracean plan` against the bundled testbed DLL |
| `testbed-trace.jsonl` | A trace of the two hooks in that plan firing |

```bash
frustracean replay docs/examples/testbed-trace.jsonl --plan docs/examples/testbed-plan.json
```

## Where the numbers come from

Every measurement in the trace is real. The bundled fixture
(`crates/frustracean-testbed`) packs and unpacks itself, and it can dump each
stage:

```bash
frustracean-testbed --dump ./stages
```

```bash
frustracean stats ./stages/stage0-packed.bin
```

The entropies, chi-square values, byte counts, and SHA-256 hashes in
`testbed-trace.jsonl` are exactly what `frustracean stats` reports for those
dumps. Regenerate them yourself and they will match.

## What is and is not real here

The **plan** is genuine output — `frustracean plan` produced it.

The **trace** is hand-authored, because the detour stub that would produce it is
not implemented yet (see `crates/frustracean-hook/src/detour.rs`). It is not an
illustration, though: it is written to the same schema the payload emits, parsed
by the same code, and populated with the fixture's real measurements. When the
stub is brought up against the testbed, its output should match this file
modulo addresses, timings, and thread ids.

That makes this trace the acceptance criterion for the remaining work, which is
why it is checked in rather than generated.

## Portability

`testbed-plan.json` records the SHA-256 of the DLL it was built against. Your
build of the testbed will hash differently, so `frustracean trace` will refuse
to use this plan against it — deliberately, since a plan applied to a different
binary would hook whatever happens to sit at those offsets.

`replay` does not check the hash, because it only reads the plan to recover each
rule's entropy expectation. To get a plan matching your own build:

```bash
frustracean plan target/release/frustracean_testbed_payload.dll --out plan.json
```
