# Code of conduct

## The short version

Be decent. Assume good faith. Criticise work, not people.

## What is expected

- Keep technical disagreement technical. "This argument model is wrong because
  the return type is 17 bytes" is useful. "This is amateurish" is not.
- Accept that the maintainer may decline a change. The scope in
  `CONTRIBUTING.md` is deliberately narrow.
- Respect the reporting process in `SECURITY.md`. Crashes on crafted input go
  through private advisories, not public issues.

## What is not

Harassment, personal attacks, or discriminatory language of any kind. Sustained
disruption of discussion. Publishing others' private information.

There is one project-specific rule, and it is not negotiable: **do not attach
live malware to issues, pull requests, or discussions.** Reduce it to a crafted
fixture, or report privately. Anyone reading this repository should be able to
clone it without acquiring a sample they did not ask for.

## Scope

This applies in the issue tracker, pull requests, discussions, and anywhere
someone is representing the project.

## Enforcement

Report concerns to the maintainer through a GitHub issue, or privately via the
Security tab if the report itself is sensitive. Reports will be handled
discreetly. Responses range from a request to change behaviour, through removal
of comments, to a block — proportionate to what happened.

This is a small project maintained by one person. Expect judgement rather than
process.
